# چک‌لیست تحویل و راه‌اندازی عملیاتی فروشگاه

این راهنما برای زمانی است که دامنه و هاست نهایی انتخاب شده باشد. مواردی که نیازمند حساب واقعی یا دسترسی سرور هستند، از داخل CI قابل تأیید نیستند.

## ۱. پیش از انتقال

- [ ] مخزن را از نسخه نهایی main دریافت کنید.
- [ ] وجود composer.lock را بررسی کنید؛ نصب وابستگی‌ها باید با composer install انجام شود، نه composer update.
- [ ] نسخه PHP را حداقل 8.3 و افزونه‌های لازم Laravel را بررسی کنید.
- [ ] یک دیتابیس MySQL جداگانه برای فروشگاه بسازید.
- [ ] فایل .env را فقط روی سرور بسازید؛ هیچ secret را در Git قرار ندهید.
- [ ] APP_ENV=production، APP_DEBUG=false، APP_URL=https://... و APP_KEY اختصاصی تنظیم شوند.
- [ ] SESSION_SECURE_COOKIE=true و HTTPS فعال باشند.
- [ ] اطلاعات دیتابیس، زرین‌پال و 0098 فقط در متغیرهای محیطی یا Secret Manager ذخیره شوند.

## ۲. ایمن‌سازی وب‌سرور

- [ ] Document Root دامنه دقیقاً روی پوشه public پروژه باشد.
- [ ] پوشه‌های app، bootstrap، config، database، resources، routes، storage، vendor و فایل .env از وب قابل دسترسی نباشند.
- [ ] دسترسی نوشتن فقط به storage و bootstrap/cache داده شود.
- [ ] HTTPS معتبر، تمدید خودکار گواهی و ریدایرکت HTTP به HTTPS فعال باشد.
- [ ] WAF/CDN و rate limit لایه شبکه برای حملات حجمی و درخواست‌های مخرب فعال شود.
- [ ] دسترسی عمومی به log، backup، فایل‌های مخفی و directory listing مسدود باشد.

## ۳. نصب و اجرای Laravel

از ریشه پروژه روی سرور:

    composer install --no-dev --prefer-dist --optimize-autoloader
    php artisan key:generate
    php artisan migrate --force --seed
    php artisan storage:link
    php artisan optimize

**هشدار:** key:generate را فقط برای نصب تازه اجرا کنید؛ روی فروشگاه فعال، APP_KEY را بدون برنامه مهاجرت عوض نکنید، چون داده‌های رمزنگاری‌شده از جمله کلید TOTP مدیر دیگر قابل رمزگشایی نخواهند بود.

## ۴. مدیر و تأیید دومرحله‌ای

- [ ] حساب مدیر را فقط با فرمان امن ساخت مدیر که در README توضیح داده شده بسازید.
- [ ] رمز مدیر قوی، یکتا و غیرقابل استفاده در سایت‌های دیگر باشد.
- [ ] در اولین ورود، کلید TOTP را در برنامه‌ای مانند Aegis یا Google Authenticator ثبت و کد را تأیید کنید.
- [ ] کلید محرمانه را در محل امن خارج از سرور نگهداری کنید.
- [ ] اگر دستگاه گم شد، پس از احراز مالکیت سرور، از فرمان php artisan admin:mfa-reset 09xxxxxxxxx استفاده کنید؛ سپس مدیر باید دوباره MFA را ثبت کند.
- [ ] پنل مدیریت را فقط در اختیار افراد مجاز قرار دهید.

## ۵. زرین‌پال و پیامک

- [ ] ابتدا زرین‌پال Sandbox را با پرداخت موفق، لغو، callback تکراری و verify آزمایش کنید.
- [ ] پس از تأیید مالک فروشگاه، Merchant ID و URLهای رسمی Production را در محیط سرور وارد کنید.
- [ ] با یک پرداخت کم‌مبلغ واقعی، ثبت تراکنش و تطبیق مبلغ/Authority را کنترل کنید.
- [ ] اطلاعات حساب 0098 و URL اختصاصی را از پنل صاحب حساب دریافت کنید.
- [ ] ارسال OTP، پیامک پرداخت، ارسال مرسوله و تحویل را روی شماره‌های مجاز آزمایش کنید.
- [ ] پیامک‌های ناموفق و پاسخ API را پایش کنید؛ URL لینک ارسال 0098 ممکن است اعتبارنامه را در log درخواست ثبت کند، پس دسترسی logها محدود و محرمانه باشد.
- [ ] هیچ‌گاه موفقیت پرداخت یا پیامک را فقط بر اساس پیام مرورگر یا callback تأییدنشده فرض نکنید.

## ۶. تست فروشگاه و محتوا

- [ ] تمام صفحات اصلی، فروشگاه، دسته‌بندی، جزئیات محصول، سبد و checkout را روی موبایل و دسکتاپ آزمایش کنید.
- [ ] تصاویر واقعی محصولات، گالری و مدل‌های GLB معتبر را بارگذاری کنید.
- [ ] نام، لوگو، رنگ، نشانی، شماره پشتیبانی، هزینه ارسال و روش تحویل را از پنل تنظیم کنید.
- [ ] یک سفارش آزمایشی را از ثبت تا پرداخت، آماده‌سازی، ارسال و تحویل دنبال کنید.
- [ ] رزرو و آزادسازی موجودی، کوپن، لغو سفارش و callback تکراری را آزمایش کنید.
- [ ] متن قوانین، حریم خصوصی و شرایط مرجوعی را با سیاست واقعی فروشگاه و الزامات قانونی تطبیق دهید.
- [ ] تست هم‌زمانی رزرو و کسر موجودی را روی همان نسخه MySQL سرور اجرا کنید؛ CI فعلی SQLite است.

## ۷. پشتیبان‌گیری و نگهداری

- [ ] از دیتابیس و storage/app/public نسخه پشتیبان رمزنگاری‌شده تهیه کنید.
- [ ] حداقل یک بار بازیابی کامل backup را روی محیط جداگانه تمرین کنید.
- [ ] Scheduler لاراول را هر دقیقه از Cron اجرا کنید تا رزروهای منقضی پاک‌سازی شوند.
- [ ] خطاهای Laravel، ورودهای ناموفق، پیامک ناموفق و وضعیت پرداخت‌ها پایش شوند.
- [ ] Dependabot و Composer audit را فعال نگه دارید و هر به‌روزرسانی را ابتدا در محیط آزمایشی تست کنید.
- [ ] پس از تغییر دسترسی کارکنان یا احتمال افشای رمز، رمزها و کلیدهای مربوط را تعویض کنید.

## وضعیت فعلی

تست‌های خودکار کد، migrationها، قالب‌ها، JavaScript و وابستگی‌ها در GitHub Actions اجرا می‌شوند. این تست‌ها جای تست نفوذ مستقل، تست MySQL واقعی، حساب Sandbox/Production زرین‌پال، پیامک واقعی، تنظیمات هاست و بازیابی backup را نمی‌گیرند.
